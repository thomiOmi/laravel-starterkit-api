# Phase 1 Quality Foundation - Plan 01: Rate-Limit Contract Verification (TDD)

## Objective

**As an API consumer, I want every auth endpoint to expose the rate-limit contract (X-RateLimit headers on 2xx/4xx, full ProblemResponse plus Retry-After and X-RateLimit-Reset on 429) and the SuccessResponse/ProblemResponse envelope, so that clients back off correctly and the shipped API contract is verified end-to-end.** This plan closes the API-02 and API-03 verification gaps and repairs the defect the verification proves (D-10). Research empirically confirmed the defect: the TooManyRequestsHttpException renderer in bootstrap/app.php (lines 130-138) constructs ProblemResponse without forwarding $e->getHeaders(), so every 429 drops all rate-limit headers.

- Tests run against real routes (POST /api/v1/auth/*, API-01 exercised implicitly) using the existing module-test infrastructure (D-05, D-06).
- This is a TDD plan: two RED tasks write the failing contract tests first, then one GREEN task applies the production fix and the unit-level regression guard.

**Artifacts this phase produces:** modules/IAM/Tests/Feature/AuthRateLimitTest.php (new contract suite covering login, register, forgot-password, reset-password with per-email and per-IP scenarios plus one success-flow test), the headers: $e->getHeaders() line in bootstrap/app.php, one assertHeader('Retry-After', '60') line in tests/Unit/Http/Exceptions/ExceptionHandlerTest.php. The phpstan.neon exclude removal lives in Plan 02.
